# NightBus

Учебный игровой проект для **Sinclair ZX Spectrum 128K** на Z80 assembler.
Разработка игры и изучение Z80 идут одновременно: в проект не добавляется «магический» код,
который мы не разобрали хотя бы на практическом уровне.

## Целевая платформа

Основная цель с самого начала — ZX Spectrum 128K:

- 128 KiB RAM с банковым переключением через `$7FFD`;
- AY-3-8912;
- обычный экран Spectrum;
- совместимость с ZX Evolution как с реальным железом.

48K не является архитектурной целью проекта.

## Окружение

- SjASMPlus
- Fuse
- GNU Make
- Git
- Sinclair 128K ROM: `128-0.rom`, `128-1.rom`

По умолчанию `r` ищет ROM в:

```text
~/.local/share/fuse/roms/
```

Путь можно переопределить переменной `FUSE_ROM_DIR`.

## Сборка

```bash
make
```

Результат:

```text
build/nightbus.tap
```

TAP содержит BASIC-loader и машинный код, который загружается по адресу `$8000`.

## Запуск

```bash
./r
```

`r` проверяет инструменты и ROM, собирает TAP и запускает Fuse именно как
Sinclair ZX Spectrum 128K. Окно увеличивается фильтром `3x`, а Fuse использует
128K menu/phantom typist для автоматического запуска TAP.

## Карта памяти

```text
$0000-$3FFF   ROM
$4000-$7FFF   RAM bank 5   основной экран
$8000-$BFFF   RAM bank 2   постоянный код и данные
$C000-$FFFF   RAM bank N   переключаемое окно, bank 0..7
```

Выбор банка в `$C000-$FFFF` выполняется через порт `$7FFD`.

## Структура

```text
NightBus/

├── versions.md
├── build/
└── src/
    ├── main.asm
```

`memory.asm` содержит карту памяти и аппаратные адреса.
`paging.asm` содержит минимальную процедуру переключения RAM-банков.
`tape.asm` формирует загрузочный TAP.

## Direct 128K development snapshot

Для повседневной разработки `./r` больше не использует Tape Loader.

Сборка создаёт:

```text
build/nightbus.tap   — образ для реального ZX Spectrum / ZX Evolution
build/nightbus.bin   — машинный код фиксированного банка
build/nightbus.z80   — development snapshot для Fuse
```

`nightbus.z80` — Z80 snapshot v3 с явно заданной машиной Sinclair 128K.
Код кладётся в физический RAM bank 2 (`$8000-$BFFF`), а PC сразу указывает
на `start`, поэтому Fuse начинает выполнять программу без BASIC, ленты,
phantom typist и tape traps.

Это dev-механизм. TAP продолжает собираться отдельно и остаётся форматом
для проверки на реальном железе.

## v0.0.9: первый игровой цикл

Первый анимационный тест использует уже настоящий цикл игры:

```text
main_loop
    clear_screen
    draw_line
    wait_frame
    move_line
    repeat
```

Новые инструкции на этом шаге:

- `CALL` — вызвать подпрограмму;
- `RET` — вернуться из неё;
- `HALT` — ждать аппаратного прерывания;
- `EX DE,HL` — поменять местами пары регистров;
- `ADD HL,DE` — 16-битное сложение адресов.

Линия перемещается по экрану с шагом 8 пикселей. Адрес строки пока берётся
из учебной таблицы `line_addresses`; позже заменим её вычислением адреса
экрана Spectrum.

## v0.0.10: движение по одному пикселю

Линия больше не прыгает по строкам знакомест с шагом 8 пикселей.
`line_y` теперь проходит весь диапазон `0..191`.

Добавлена `screen_address`:

```text
A = Y
↓
screen_address
↓
HL = адрес начала соответствующей pixel row
```

У ZX Spectrum bitmap имеет нелинейную раскладку в памяти, поэтому адрес
строки нельзя получить простым `SCREEN_ADDR + Y * 32`.

На этом шаге синхронизация по кадрам ещё не используется: задержка остаётся
программной. Следующий отдельный шаг — 50 Гц frame sync.

## v0.0.11: 50 Гц и плавный render loop

Анимация теперь привязана к аппаратному кадру Spectrum:

```text
HALT
→ erase old line
→ Y = Y + 1
→ draw new line
→ следующий HALT
```

То есть линия двигается ровно на один пиксель за один кадр (~50 Гц).

Также исправлена функция `screen_address`: младшие биты `Y2..Y0`
должны попадать прямо в младшие биты `H`, без вращения.

Полная очистка 6144 байт видеопамяти теперь выполняется только при старте.
Во время анимации стираются и рисуются всего по 32 байта, поэтому render loop
намного легче и не должен рвать изображение.

Для frame sync используется компактный IM2:

```text
I = $90
vector = $90FF
handler address записывается туда при старте
```

Обработчик находится рядом с обычным кодом — никаких больших `ORG` и
16-КБ дыр в dev binary.

## v0.0.13: первый управляемый объект

Автодвижение убрано. На экране теперь один пиксель — первый игровой маркер.

Игровой цикл:

```text
HALT
→ erase_player
→ read_keyboard
→ draw_player
→ repeat
```

Управление:

```text
←  = Spectrum key 5
↓  = Spectrum key 6
↑  = Spectrum key 7
→  = Spectrum key 8
```

На настоящем ZX Spectrum cursor keys являются сочетаниями
`CAPS SHIFT + 5/6/7/8`. Код читает сами клавиши `5..8`, поэтому состояние
`CAPS SHIFT` ему не мешает. В Fuse можно использовать стрелки, если они
замаплены стандартно, либо цифровые `5/6/7/8`.

Позиция хранится отдельно:

```text
player_x = 0..255
player_y = 0..191
```

Движение — один физический пиксель за один кадр.
